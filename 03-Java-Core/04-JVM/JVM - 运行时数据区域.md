# JVM - 运行时数据区域

## 一句话解释
程序运行时，JVM 把内存分成堆、栈、方法区等几块，各管各的事，就像公司分财务部、技术部、人事部。

## 为什么存在
Java 程序需要内存来存数据、执行方法、记录行号，JVM 通过划分不同区域来**分类管理**，提高效率和安全性。

## 核心原理
1. **程序计数器**：记录当前线程执行到第几行字节码，线程私有，不会 OOM
2. **虚拟机栈**：每个方法执行时创建一个栈帧，存局部变量、操作数栈、动态链接，线程私有
3. **本地方法栈**：给 Native 方法用的，和虚拟机栈类似
4. **堆**：存所有对象实例和数组，线程共享，**GC 的主要区域**
5. **方法区**（元空间）：存类信息、常量、静态变量、即时编译器编译后的代码
6. **直接内存**：NIO 用的，不受 JVM 堆大小限制

## 类比/关联
- 类似于 [[操作系统 - 进程内存布局]]
- 和 [[JVM - 堆内存与GC]] 的关系：堆是运行时数据区域中最大的一块，也是 GC 的重点
- 和 [[Java - 栈与堆的区别]] 的关系：栈存引用，堆存对象

## 实际应用
排查内存问题时先看哪个区域溢出：
- `StackOverflowError` → 栈太深，无限递归
- `OutOfMemoryError: Java heap space` → 堆满了，对象太多
- `OutOfMemoryError: Metaspace` → 方法区/元空间满了，类加载太多
